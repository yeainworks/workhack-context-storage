# workhack-context-storage

Общая память WorkHack для двух людей и нескольких нейронок. Контекст и журнал действий лежат в одном бакете Cloudflare R2. Каждая сессия **начинается** с чтения контекста и **заканчивается** записью итога. Ничего не теряется, контекст одинаковый у всех.

## Быстрый старт (zip в нейронку)
1. Распакуй архив. Открой Claude Code или Codex в папке `workhack-context-storage`.
2. Напиши: **«Прочитай INSTALL.md и выполни установку. Папка проекта WorkHack: `<путь>`»**
3. Партнёр заранее присылает тебе (Bitwarden, не чат): Account ID, имя бакета, Access Key ID, Secret Access Key.
4. Агент попросит тебя выполнить `wh setup` в терминале и вставить эти четыре значения. Секрет в чат не уходит.
5. Конец: `wh doctor` показывает пять ✓.

Дальше как работать: **[docs/USAGE.md](docs/USAGE.md)**.

## Как это устроено
```
 Claude Code ──хуки──► wh ──► R2 бакет
   SessionStart     читает context/, события, последние сообщения, claim → кладёт в начало сессии
   UserPromptSubmit пишет каждое твоё сообщение в messages/
   Stop             пишет ответ ИИ в messages/; не даёт закончить, пока не записан итог (один раз)
   PreCompact       пишет checkpoint перед сжатием контекста
   SessionEnd       если итога не было, пишет «закончилась без итога»

 Codex ──wh-codex──► подставляет контекст в первый запрос, после выхода пишет session-end
 (+ AGENTS.md: правила и те же команды, без принудительного финиша)
 ChatGPT (чат) ──► wh pack / wh ingest (файл-мост, вручную)
```
Бакет:
```
context/*.md                  общий контекст (core.md грузится всегда)
events/ГГГГ-ММ-ДД/…json       журнал, только добавление
messages/ГГГГ-ММ-ДД/…json     журнал сообщений: твои и ответы ИИ (wh config log_messages full|prompts|off)
claims/ done/                 кто взял задачу / что закрыто (атомарно)
assets/ queue/ ready/         картинки, посты на проверку, готовые пакеты
```

## Надёжность и ограничения (честно)
- **Claude Code:** старт и финиш принудительные (хуки). Это основной путь.
- **Codex:** только инструкция в `AGENTS.md`. Забыть может. Команды `wh` пишут сами, но «финиш» не принудителен.
- **ChatGPT в чате:** доступа к бакету нет, работает мост `pack` / `ingest` вручную.
- **Нет сети:** старт честно пишет «КОНТЕКСТА НЕТ»; записи копятся в очереди `~/.workhack/outbox` и уходят позже.
- **R2 без версионирования:** события не перезаписываются никогда; общие файлы контекста правятся осознанно (`docs/USAGE.md`, раздел 7).
- **Windows:** `install.ps1` написан, но не проверялся на реальной Windows.
- Claim использует условную запись `If-None-Match` / `If-Match`. `wh doctor` проверяет, что R2 её поддерживает.

## Что проверено, а что нет
Проверено:
- 34 автотеста (подпись SigV4 по примеру AWS, запись, чтение, claim, очередь без сети, хуки, журнал сообщений, обёртка Codex, мост для чата).
- `wh doctor` на настоящем бакете R2: 6 из 6, включая условные записи для claim.
- `bash install.sh` целиком на подмене S3: настройка, `doctor`, заливка контекста, подключение проекта.
- Реальный Claude Code с плагином (`--plugin-dir`): `claude plugin validate` проходит, видны скилл и 4 хука; хук `SessionStart` положил контекст в сессию, хук `SessionEnd` записал событие в журнал.

НЕ проверено (нужны ваши данные или другие машины):
- Работа с **настоящим R2**: сначала запусти `wh doctor`, он проверит запись, чтение и условные записи.
- **Принудительный финиш** (хук `Stop`) в живой сессии с моделью: при моей проверке токен Claude в песочнице истёк, модель не ответила. Формат ответа хука стандартный и покрыт тестами, но в живую при вас он не гонялся.
- Windows и Codex.

## Структура репозитория
```
bin/wh.py, wh, wh.cmd     CLI (только стандартная библиотека Python 3.9+)
bin/wh-codex              запуск Codex с контекстом из бакета
hooks/hooks.json          хуки Claude Code
skills/workhack/          скилл с правилами работы
skills/workhack-autostart/ скилл: проверка и починка автозапуска, журнал сообщений
docs/AUTOSTART.md         автозапуск и журнал сообщений: инструкция
.claude-plugin/           манифест плагина и локального маркетплейса
seed/context/             начальный контекст (core.md, runbook-full.md)
install.sh / install.ps1  установка
tests/                    тесты (запуск ниже)
docs/USAGE.md             инструкция для людей
INSTALL.md                инструкция для агента
AGENTS.md / CLAUDE.md     правила для агентов внутри этого репозитория
```

## Тесты
```bash
python3 -m unittest discover -s tests -v
```
Реальный бакет не нужен: проверяется подпись SigV4 по примеру из документации AWS, а S3 подменён локальным моком.

## Секреты
В репозитории **нет** ключей. Они вводятся командой `wh setup` и лежат только в `~/.workhack/credentials` (права 600).
