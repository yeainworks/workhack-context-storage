# Как с этим работать: пошаговая инструкция

Для людей. Установку агентом читай в [INSTALL.md](../INSTALL.md).

## 0. Что это даёт
У вас с партнёром один общий бакет Cloudflare R2. В нём лежит контекст проекта и журнал действий. Любая нейронка на любом устройстве:
1. в начале сессии читает контекст и последние события,
2. перед задачей «занимает» её, чтобы второй не сделал то же самое,
3. в конце записывает, что сделала.

Ничего не теряется, контекст у вас одинаковый.

## 1. Что партнёр присылает (и как)
Партнёр создаёт в Cloudflare **R2 → бакет** (private) и **API-токен**. Права токена: `Object Read & Write`, только на этот бакет. Лучше отдельный токен каждому человеку.

Тебе нужны четыре значения:

| Что | Где взять |
|---|---|
| Account ID | Cloudflare → R2 → справа «Account ID» |
| Имя бакета | как назвали при создании |
| Access Key ID | показывается один раз при создании токена |
| Secret Access Key | там же, один раз |

**Как передавать:** через Bitwarden (общая запись) или лично. Не в обычный чат, не в GitHub, не в письмо. Если секрет попал в чат: в Cloudflare удалить токен и создать новый (30 секунд).

## 2. Установка (один раз на устройство)
**Способ А, через нейронку (проще).** Распакуй zip. Открой Claude Code (или Codex) в папке `workhack-context-storage` и напиши:

> Прочитай INSTALL.md и выполни установку. Папка проекта WorkHack: `/Users/vladimirg.sergeev/ALL WORKS/Projects/workhack`

Когда агент скажет «введи данные R2 сам», открой терминал, выполни `wh setup` и вставь 4 значения. Секрет вводится скрыто. Агенту ничего из этого присылать не нужно.

**Способ Б, руками.**
```bash
cd workhack-context-storage
bash install.sh --project "/Users/vladimirg.sergeev/ALL WORKS/Projects/workhack"
```
Windows (PowerShell): `.\install.ps1 -Project "C:\...\workhack"`

Установка успешна, если в конце `wh doctor` показывает пять зелёных ✓ и «всё работает».

## 3. Каждый день: Claude Code (основной путь)
1. Открой Claude Code **в папке проекта WorkHack** (или любой её подпапке). Хук сам загрузит контекст. Ты увидишь в начале сессии блок «WorkHack: общий контекст».
2. Работай как обычно: «сделай 3 поста на сегодня».
3. Агент сам вызывает `wh claim`, `wh note`, `wh done`. Закончить сессию без записи итога он не сможет: хук один раз потребует `wh done`.
4. Закрыл сессию внезапно: хук `SessionEnd` запишет в журнал «сессия закончилась без итога», и партнёр это увидит.

Проверить вручную, что видит партнёр: `wh start`.

## 4. Codex (запасной путь, с терминалом)
Хуков у Codex нет. Запускай его через обёртку, она сама подставит контекст из бакета и запишет конец сессии:
```bash
/путь/к/workhack-context-storage/bin/wh-codex "задача на сегодня"
```
В конце попроси: «Запиши итог: `wh done …`». Подробнее: `docs/AUTOSTART.md`.

Журнал каждого сообщения и автозапуск в Claude Code: тоже в `docs/AUTOSTART.md`.

Строгость тут слабее, чем в Claude Code: нет принудительной записи итога. Если нейронка забыла, скажи ей: «Запиши итог командой wh done».

## 5. ChatGPT в браузере или приложении (без доступа к бакету)
ChatGPT не умеет ходить в R2, поэтому через файл-мост:
1. В терминале: `wh pack`. Появится файл `~/.workhack/pack.md`.
2. Загрузи его в чат ChatGPT и напиши задачу («сделай 3 варианта картинки утки по новости про…»).
3. В конце попроси: «Выдай ОТЧЁТ в формате из файла».
4. Скопируй отчёт в файл `report.txt` и выполни: `wh ingest report.txt --from chatgpt`. Если ChatGPT сделал картинки, сохрани их и загрузи: `wh put duck.png assets/duck-2026-11-09-тема.png`.

## 6. Шпаргалка команд
| Команда | Что делает |
|---|---|
| `wh doctor` | проверка доступа, записи, чтения, claim |
| `wh start` | показать контекст, последние события, кто что занял |
| `wh claim daily-20261109` | занять задачу (0 взял · 1 занято · 2 уже закрыта) |
| `wh note "текст"` | записать промежуточное событие |
| `wh done "итог" --task daily-20261109` | закрыть задачу, записать итог |
| `wh handoff "причина + состояние"` | передать работу дальше |
| `wh fail "что сломалось"` | записать провал |
| `wh put файл assets/имя.png` | загрузить файл в бакет |
| `wh get assets/имя.png файл` | скачать файл |
| `wh ls events/2026-11-09/` | список событий за день |
| `wh get context/core.md` | прочитать файл контекста на экран |
| `wh flush` | отправить очередь, накопленную без связи |
| `wh pack` / `wh ingest` | мост для ChatGPT |

## 7. Как обновлять общий контекст
Файлы `context/*.md` в бакете живые: правят обе стороны. Править так:
```bash
wh get context/core.md /tmp/core.md      # скачать
# отредактируй /tmp/core.md
wh put /tmp/core.md context/core.md --force
wh note "обновил core.md: что поменял"   # обязательно сообщи в журнал
```
`core.md` грузится в каждую сессию, держи его короче 2 страниц. Длинное кладите в отдельные файлы `context/…` (агент читает их по теме).

Версионирования в R2 нет: перед правкой общего файла договорись с партнёром или скачай копию.

## 8. Если не работает
| Симптом | Причина | Что делать |
|---|---|---|
| В начале сессии «КОНТЕКСТА НЕТ» | нет интернета или неверные ключи | `wh doctor`. Интернет есть, а ✗: ключи неверные, делай `wh setup` заново |
| `HTTP 403` | у токена нет прав на этот бакет | Cloudflare → R2 → токен → права `Object Read & Write` на нужный бакет |
| `HTTP 404`/«NoSuchBucket» | опечатка в имени бакета или Account ID | `wh setup` заново |
| doctor: ✗ «If-None-Match» | R2 не принял условную запись | напиши мне: claim будет работать «по честному слову», пока не починим |
| Хуки не срабатывают | сессия открыта не в папке проекта | открой Claude Code в папке WorkHack. В ней должен лежать файл `.wh-project` (создаётся `wh init-project <папка>`) |
| Хуки не срабатывают, папка верная | плагин не установлен | `claude plugin list` должен показать `workhack-context`. Нет: `claude plugin marketplace add <папка репозитория>`, затем `claude plugin install workhack-context@workhack-context-storage` |
| Записи ушли в очередь | не было связи | при следующем `wh start` или `wh flush` они отправятся сами |
| Два человека заняли одну задачу | claim не использовали | агенту напомнить правило 2 из `AGENTS.md`, проверить `wh ls claims/` |

## 9. Безопасность
- Ключи лежат только в `~/.workhack/credentials` (права 600). В репозитории их нет и не должно быть.
- Не отправляй zip с установленным `~/.workhack` и не выкладывай эту папку никуда.
- Потерял устройство или секрет попал в чат: удали токен в Cloudflare и выдай новый.
- `wh` автоматически вырезает токен-подобные строки из событий, но на это не рассчитывай: секреты в текст событий не писать.
