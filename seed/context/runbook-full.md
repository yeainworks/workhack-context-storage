=== 3. Общее состояние и передача работы (без серверов, бесплатно) ===
Общая папка в Google Drive: «AI Sync 2.0» → inbox (id 1S2KNLyXYR3o-zWL9hWxF2QekEqiVxzZK), должна быть доступна обоим людям и их агентам (Drive-коннектор). Коннектор умеет только СОЗДАВАТЬ файлы — поэтому состояние ведётся как журнал событий, существующие файлы не правим.
Имя файла: wh-YYYYMMDD-HHMM-<событие>-<RUNNER>-<задача> (время ICT). События: claim (беру задачу), done, handoff (передаю, причина), fail, note.
Задача дня = daily-YYYYMMDD. Правила:
1. Перед началом: найди файлы wh-<сегодня>-*-daily-*. Если есть done за сегодня — ничего не делай.
2. Если есть claim без done и он моложе 90 минут — работа идёт, уйди.
3. Иначе создай свой claim, подожди 60 сек, перечитай список: если до тебя (по времени создания) есть чужой claim — уступи.
4. Лестница таймаутов (ICT): R1 в 12:30 → если нет claim/done к 14:30 — R2 → к 16:30 — R3 → к 18:30 — R4.
5. Журнал постов: локальный posts-log.md на Mac A, копия итогов — в done.
Секреты (токены, пароли, коды) в Drive/чаты не писать. Токен бота у каждого устройства свой в Keychain/менеджере паролей (передавать через Bitwarden).
=== 4. Какое устройство выбрать (лестница приоритетов) ===
Задачи без интерфейса (API, скрипты, тексты): любое устройство.
Задачи с интерфейсом (agent-desktop, браузер) и тяжёлые:
1. ПК A, если им сейчас никто не пользуется (>10 мин без ввода) и он включён;
2. иначе Mac B, если свободен (>10 мин без ввода);
3. иначе Mac A, если свободен и температура <85°C (macmon/thermal-log);
4. иначе — отложить на 30 мин (но не позже следующего слота).
Проверка «кто пользуется»: macOS: ioreg -c IOHIDSystem | awk '/HIDIdleTime/{print int($NF/1000000000)}' → секунд без ввода (≥600 = свободен). Windows: GetLastInputInfo (скрипт idle.ps1 — в чек-листе). Mac A дополнительно: ~/AI Sync/bin/mac-lock.sh status claude должен быть FREE (бронь Mac с Codex), на батарее не работать.
Рендер видео, ComfyUI, локальные модели — только на ПК A (Mac Air без вентилятора не греть).
=== 5. Правила контента (нарушать нельзя) ===

- Без «кринжа»: никаких выдуманных шуток/мем-текстов; юмор — только утверждённый человеком. Нельзя, например: «Ищем джуна… горящие глаза».

- Структура поста: первая строка ⚡️ + цепкий заголовок; 3–5 коротких абзацев с цифрами и источником; ироничный вывод; подпись @hackforworks; 600–1000 знаков (подпись под фото ≤1024!). Один CTA максимум.
- Не использовать чужие видео как картинку (риск потери охватов/монетизации на YouTube/TikTok, права не подтверждены): чужое — только как повод для темы.
- Голос — только живой голос пользователя; клонировать голоса без отдельного согласия нельзя.
- Новым сервисам (Gemini, Grok, Higgsfield, ElevenLabs) клиентские данные/переписки/голос без согласия не передавать. Пароли, коды 2FA, ключи, почты в обмен не включать.
- Нельзя: покупать/платить, удалять аккаунты, писать людям, заходить в личный Telegram пользователя, вводить пароли и коды, обходить CAPTCHA.
